# 官网配置闭环优化设计

## 目标

建立单一的官网配置来源，让六套主题和官网公共页面共享品牌、导航、首页内容、统计、联系信息、页脚、SEO 与视觉变量。管理端提供分组清晰、可校验、可恢复的网站配置编辑体验。

## 范围

- 后端 `SiteConfig` 继续使用现有 `site_settings` key-value 表。
- 结构化字段以 JSON 存储，API 返回对象结构。
- 官网公共布局、主题首页、功能页、关于页、定价页和联系页使用统一配置读取器。
- 管理端合并旧首页字段与结构化字段，保留 SMTP、短信和注册设置。
- 六套主题继续保留各自的布局、颜色语言和组件节奏。

## 配置模型

配置分为六组：

1. 品牌基础：站点名称、标题、描述、Logo、主题。
2. 导航与行动：导航项、登录按钮、主行动按钮和链接。
3. 首页内容：Hero、功能卡片、统计、信任区、仪表盘示例。
4. 视觉变量：主色、强调色、背景色、正文色、弱化文字色。
5. 联系与页脚：邮箱、电话、地址、工作时间、页脚描述、版权和链接分组。
6. SEO：页面标题、描述和分享图地址。

缺失字段由服务端默认配置补齐；非法主题值归一化为 `syntro`；空数组使用默认内容，保障官网始终可渲染。

## 数据流

```text
site_settings
    -> setting.Repository
    -> GET /api/v1/settings
    -> Layout.astro / ThemeHome.astro / content pages

Admin settings form
    -> PUT /api/v1/admin/settings
    -> setting.Repository.Update
    -> site_settings
```

官网请求失败时使用本地安全默认配置。管理端请求超时或失败时结束 loading 状态，显示中文错误和重新加载入口。

## 管理端设计

- 删除重复的旧首页编辑区，改为统一的“首页内容”区。
- 使用“品牌基础、导航、首页、主题、联系、系统”六个分组。
- 对必填文本、颜色值、URL 和统计项做前端校验。
- 保存按钮展示保存中、成功和失败状态。
- API 返回旧数据时通过深合并补齐新字段，避免表单字段丢失。
- 表单保存前构造完整 `SiteConfig`，后端按字段和 JSON 结构持久化。

## 官网设计

- 新增轻量配置读取和默认合并逻辑，避免每个页面自行声明默认值。
- 公共导航、Logo、CTA、页脚和 SEO 使用配置。
- 六套主题只负责布局和视觉样式，文案与数据从配置读取。
- 所有图标使用 SVG 或 CSS 结构，页面文案不使用 emoji 和 Unicode 图标。
- 主题颜色通过 CSS 变量注入，缺失颜色时回退到主题默认值。

## 验证标准

- `services/setting` 和 `services/api` 测试通过。
- 官网、管理端生产构建通过。
- 六个主题都能在配置接口返回空值、完整值和非法主题值时正常渲染。
- 管理端设置页在 API 超时、接口失败和保存成功场景下都能结束 loading 并给出反馈。
- 官网、用户端和管理端本地入口返回 `200`。
- `git diff --check` 通过。
