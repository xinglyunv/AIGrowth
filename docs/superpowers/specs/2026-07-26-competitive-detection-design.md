# 竞争分析检测优化设计

## 目标

将 AI-Growth-Engine 的检测单元从“目标品牌 + 硬编码竞品扫描”升级为“目标品牌与项目确认竞品共同分析”，形成可校验、可解释、可聚合的竞争分析结果。

## 检测流程

```text
项目竞品配置
  -> 创建任务时生成品牌快照
  -> 每个问题和模型同时分析目标品牌与竞品
  -> 本地校验实体、证据和排名
  -> 持久化回答分析
  -> 聚合目标品牌与竞品评分
  -> 生成竞争差距报告
```

## 结果契约

每个 AI 回答的 `analysis` JSON 保存：

- `entities`: 品牌名称、角色、提及状态、提及次数、排名、情感、证据、优势和劣势。
- `comparison`: 胜出品牌、比较维度和解释。
- `validation`: 本地文本校验结果与推断标记。
- `model_name`、`model_provider`、`api_success`、`latency_ms`。

模型负责生成自然回答和结构化判断，本地分析器负责名称归一化、别名匹配、原文证据、排名边界和目标/竞品角色校验。

## 数据策略

任务创建时保存项目竞品快照，确保历史任务结果稳定。首期复用现有 `competitors` 表和 `ai_answers.analysis` JSONB，任务完成后按项目和品牌聚合提及率、前三位率、平均排名、情感和优势。

## 评分策略

每个品牌使用确定性评分：

- AI 出现率：30%
- 推荐排名：25%
- 推荐理由质量：20%
- 品牌认知完整度：15%
- 信息优势：10%

评分由本地代码计算，LLM 只提供结构化依据和证据。

## 执行可靠性

- 任务状态使用原子抢占，防止重复执行。
- 问题总数等于问题数乘模型数。
- 每个执行单元完成后更新进度。
- 单个模型失败保存失败分析并继续其余单元。
- 任务最终状态和错误信息可追踪。

## 安全与边界

- 竞品名称、别名和项目归属必须验证。
- 所有数据库操作使用参数化查询。
- Prompt 不包含密钥或内部凭据。
- 用户可见错误使用通用中文信息，详细错误仅写服务日志。

## 分阶段范围

P0 包含统一实体分析、竞品快照、结果持久化、确定性评分、任务进度和报告聚合。

P1 包含竞争品牌管理页面、竞争分析独立报告页、趋势图、来源表和差距分析 Agent。
